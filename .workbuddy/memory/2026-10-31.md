## 新功能：首页「今天吃什么」随机抽菜（v1.4）

背景：高分榜只回答"什么好吃"，回答不了"我选不出来"。加一个随机按钮把选择权交给骰子。

后端 `GET /dishes/random`（必须注册在 `/dishes/{id}` 之前）：
- 候选池规则：先高分池（`is_available` + `avg_rating>=min_rating` + `rating_count>=min_count`），池空回退到全部上架菜品；两级都空才 404。
- `exclude_id` 支撑「换一个」不原地重复；若排除后两级池都空，再退回"不排除"重抽一次，避免 404。
- 返回 `{dish, pool_size, from_top}`；`pool_size` 是当前这一池的大小，前端据此在只剩 1 道时禁用「换一个」。
- 随机实现是 `ORDER BY RAND() LIMIT 1`（小表够用）；count 用 `stmt.with_only_columns(func.count()).order_by(None)` 复用同一 FROM/WHERE。

前端 `RandomDishDialog.vue`：
- 打开即抽；摇骰子最短 640ms（秒出没有"抽"的感觉），三颗骰子错开 0.13s 相位。
- 揭晓卡片 key 绑定 `rolled` 计数，重播 pop 动画；`换一个` 传 exclude、`就吃这个` 关弹窗并跳详情。
- 池子只剩一道时按钮禁用 + title 说明，不骗点击。
- 弹窗 `width="min(440px, 92vw)"`，375px 下不溢出。

顺手修：`DefaultLayout` 在 560px 以下导航被挤成逐字竖排（`.nav-link` 缺 `white-space: nowrap`）。改为品牌 + 登录按钮第一行、导航第二行横向滚动。

测试：journey 85/85（新增 5 条随机接口断言，注意本项目校验错误是 400/40001 而非 422）、smoke 70/70；type-check 通过；build 首屏 JS 仍 ~131KB（HomeView chunk 9KB）。
文档同步：README 功能列表、PDR 2.3.1（v1.4 段）、TechDesigh 3.3.3 接口表、AGENTS 决策 17（后端抽，不要前端 Math.random）。

## 新功能：首页「关注」流（v1.5）

诊断：关注能力早就有了（follows 表、单向关注、互关 EXISTS、个人页粉丝/关注列表），但首页 feed 只有 latest/hot，关注完回首页看到的还是全站流——功能建了没有出口。

后端：`/posts/feed?sort=following`
- 必须登录，未登录 `Unauthorized` → 401/40101（**不要**返回空列表，否则前端分不清"没登录"和"没关注人"）
- 只含我关注的人，**不含我自己**（自己的动态在个人主页看）
- 过滤：`Post.user_id.in_(select(Follow.following_id).where(...))`，不要 join follows（帖子对关注没有多对多，join 还要 distinct）
- 排序走默认 created_at desc；`keyword` 可与 following 叠加

前端 HomeView：
- tab 改成 `TABS` 常量数组 + `SortKey` 类型，关注 tab 后面带 `following_count` 小标
- 未登录点关注：**不发请求**，直接渲染登录引导卡片
- 空态两套文案：`following_count` 为 0 → "还没关注任何人"（教用户去作者主页关注）；否则 → "关注的人还没发帖"
- `watch(sort)` 先清空 posts/total 再请求，避免切 tab 时旧内容串台

测试：journey 93/93（新增 8 条）、smoke 70/70；CDP 实测三态：游客引导 / xiaoming「关注 1」2 帖（作者仅拉面忠粉）/ ada（关注 0）空态。

提交 `a6646de`，已推送。文档同步 README、PDR 2.3.1、TechDesigh 3.3.4、AGENTS 决策 18。

## 新功能：想吃清单 + 抽签联动（v1.6）

目标是把 存 → 抽 → 吃 → 评 串成闭环。之前「随机一顿」的池子是全站/高分池，用户没有"自己挑过"的入口。

数据：新表 `wants(user_id, dish_id)` 复合主键 + `idx_wants_dish`，迁移 `3c1f9a2b7d54`。它只是标记，**不进评分**。

后端：
- `POST /dishes/{id}/want` 幂等翻转，返回 `{wanted, want_count}`；下架菜拒绝加入（400）
- `GET /users/{id}/wants` 分页，最近加的在前；下架菜仍返回（前端标「已下架」）
- 菜品详情 `with_want=True` 才查 `want_count/is_wanted`——后台列表逐条 COUNT 会 N+1，所以做成开关
- `GET /dishes/random?source=wants`：只在自己的清单里抽，**池空就 404 不回退**（用户挑的池子要尊重）
- `RandomDishOut.from_top` 改成 `source: top|all|wants`（破坏性变更，journey 断言已同步）
- 发帖成功后 `delete wants`：吃过就不算想吃
- 管理员删菜品时先清 `wants`：想吃不是内容引用，不该让删除变成 409

前端：
- 菜品页「想吃 / 已想吃 + 人数」，未登录点它跳登录
- 个人中心新增「想吃」页签，**懒加载**（不跟着首屏 6 个请求一起发），本人可移除
- 抽签弹窗顶部两个 chip：随便抽 / 从想吃里抽(N)；未登录或清单空时禁用并给一句提示
- 顺手修了移动端菜品页「暂无」被挤成竖排（`.big{white-space:nowrap}`）

测试：journey 114/114（新增 18 条）、smoke 72/72（下架不能加、想吃不挡删除）；CDP 实测游客/空清单/有清单三种状态与 375px 排版。

提交 `3219057`，已推送。文档：README、PDR（v1.6 段）、TechDesigh（wants 建表 + 4 个接口）、AGENTS 决策 19。

## 新功能：图片大图预览（v1.8）

新增 `components/ImageViewer.vue`：全屏遮罩 + 左右翻页（按钮与 ←/→ 键）+ Esc/点遮罩关闭 + 「2 / 4」页码；打开时 `document.body.style.overflow='hidden'` 锁背景滚动，卸载时复原。

关键取舍：
- **不用 `el-image-viewer`**：它要额外带样式与 popper 依赖，而帖子列表里每张卡片都会挂预览组件，包体敏感。自绘约 100 行，PostCard chunk 只从 10.3KB → 12.4KB。
- **手势分场景**：列表点图仍是"进帖子详情"（`detail ? openViewer : goDetail`），只有详情页点图才看大图；菜品详情封面可点开。否则最大的点击区域被抢走，用户想读帖子反而点不开。
- **矢量图才放大**：种子封面是 SVG，`src.endsWith('.svg')` 时 `width: min(88vw, 860px)`；位图保持原尺寸（放大只会糊）。

验证：CDP 实测列表点图 → `/posts/213`（未开预览）、详情点第二张 → 遮罩显示「2 / 2」、→ 键翻页、Esc 关闭且 overflow 复原；375px 下无横向溢出、单图不显示箭头。测试帖已删除，数据回到 8 帖 / 麻辣烫 4.67(3)。

## 站内通知（提交 f6df86d）

新表 `notifications`（迁移 `8d4b2e6a91c7`）：`user_id`(接收者) / `actor_id`(触发者) / `type`(like|comment|follow) / `post_id` / `comment_id` / `is_read`，三个外键全部 `ON DELETE CASCADE`，索引 `(user_id, is_read, created_at)`。

三条不变式（写进 AGENTS 决策 23）：
- **不给自己发**：`user_id == actor_id` 直接 return。
- **同一事件只留一条**：`push()` 先 `DELETE` 同 `(接收者, 触发者, 类型, 帖子)` 的旧行再插入 —— 取消点赞再点只刷新时间，不堆五条"赞了你"。
- **跟着源数据消失**：删帖 / 删评论靠 CASCADE；**点赞撤回和取关必须显式 `notify_service.revoke()`**（那是删边不是删行，CASCADE 管不到）。

接口：`GET /notifications`（`unread_only`）、`GET /notifications/unread-count`、`POST /notifications/read`、`POST /notifications/{id}/read`（别人的 id 按 404，不暴露存在性）。

前端：`stores/notify.ts` 管未读角标（60s 轮询，`document.hidden` 跳过；登录态变化时 start/stop）；`NotificationsView` 两个页签、点击即已读并跳原帖或对方主页、「全部已读」在未读页签下自动退回全部。

踩坑：`author_brief` 原本在 `post_service`，`notify_service` 反向 import 导致启动即 `ImportError`（partially initialized module）。抽到 `app/services/dto.py` 解决，这条也写进了 AGENTS 决策 24。

种子通知由 `likes/comments/follows` 用 `INSERT ... SELECT` 派生（51 条），保证"通知说有 3 人赞你、帖子只有 1 个赞"这种矛盾不会出现在演示里；关注类标记为已读，留赞和评论当未读给铃铛红点。

## 发帖结果面板（提交 7277667）

`CreatePostView` 成功后不再 `router.push`，原地换成 `components/PostResultPanel.vue`：我打的几分 → 这道菜现在几分（几人评过）→ 离高分榜多远。上榜显示「第 N 位」，未上榜给可执行提示（"再有 1 位同学评过" / "均分到 4.0，还差 0.5 分"）。底部三个出口：再发一条（清空评分/文案/图片但保留已选菜品）、看这道菜、回首页。

名次由页面查 `/dishes/top` 后传进组件，**不达标不查**；查榜失败只影响名次那一行，不影响"发布成功"。

**顺带挖出一个真 bug**：`_recalc_dish()` 用裸 `UPDATE` 改 `dishes` 聚合，会话里的 `Dish` 对象不会跟着变，而 `expire_on_commit=False` 让它在 commit 后也不失效 → 发帖响应里的 `dish` 是**重算前的快照**，首次评价会显示「0.0 分 / 0 人评过」。修法：`_recalc_dish` 末尾 `db.get(Dish)` + `db.refresh(dish)`。smoke 补了 2 条断言锁住这个契约（74/74）。

数据核对：种子重置后 20 菜 / 8 帖 / 高分榜 4 道（麻辣烫 4.67、牛肉拉面 4.67、卤肉饭 4.5、鸡胸沙拉 4.5）。
