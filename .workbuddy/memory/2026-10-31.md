## 新功能：首页「今天吃什么」随机抽菜（v1.4）

背景：高分榜只回答"什么好吃"，回答不了"我选不出来"。加一个随机按钮把选择权交给骰子。

后端 `GET /dishes/random`（必须注册在 `/dishes/{id}` 之前）：
- 候选池规则：先高分池（`is_available` + `avg_rating>=min_rating` + `rating_count>=min_count`），池空回退到全部上架菜品；两级都空才 404。
- `exclude_id` 支撑「换一个」不原地重复；若排除后两级池都空，再退回"不排除"重抽一次，避免 404。
- 返回 `{dish, pool_size, from_top}`；`pool_size` 是当前这一池的大小，前端据此在只剩 1 道时禁用「换一个」。
- 随机实现是 `ORDER BY RAND() LIMIT 1`（小表够用）；count 用 `stmt.with_only_columns(func.count()).order_by(None)` 复用同一 FROM/WHERE。

前端 `RandomDishDialog.vue`：
- 打开即抽；摇骰子最短 640ms（秒出没有"抽"的感觉），三颗骰子错开 0.13s 相位。
- 揭晓卡片 key 绑定 `rolled` 计数，重播 pop 动画；`换一个` 传 exclude、`就吃这个` 关弹窗并跳详情。
- 池子只剩一道时按钮禁用 + title 说明，不骗点击。
- 弹窗 `width="min(440px, 92vw)"`，375px 下不溢出。

顺手修：`DefaultLayout` 在 560px 以下导航被挤成逐字竖排（`.nav-link` 缺 `white-space: nowrap`）。改为品牌 + 登录按钮第一行、导航第二行横向滚动。

测试：journey 85/85（新增 5 条随机接口断言，注意本项目校验错误是 400/40001 而非 422）、smoke 70/70；type-check 通过；build 首屏 JS 仍 ~131KB（HomeView chunk 9KB）。
文档同步：README 功能列表、PDR 2.3.1（v1.4 段）、TechDesigh 3.3.3 接口表、AGENTS 决策 17（后端抽，不要前端 Math.random）。

## 新功能：首页「关注」流（v1.5）

诊断：关注能力早就有了（follows 表、单向关注、互关 EXISTS、个人页粉丝/关注列表），但首页 feed 只有 latest/hot，关注完回首页看到的还是全站流——功能建了没有出口。

后端：`/posts/feed?sort=following`
- 必须登录，未登录 `Unauthorized` → 401/40101（**不要**返回空列表，否则前端分不清"没登录"和"没关注人"）
- 只含我关注的人，**不含我自己**（自己的动态在个人主页看）
- 过滤：`Post.user_id.in_(select(Follow.following_id).where(...))`，不要 join follows（帖子对关注没有多对多，join 还要 distinct）
- 排序走默认 created_at desc；`keyword` 可与 following 叠加

前端 HomeView：
- tab 改成 `TABS` 常量数组 + `SortKey` 类型，关注 tab 后面带 `following_count` 小标
- 未登录点关注：**不发请求**，直接渲染登录引导卡片
- 空态两套文案：`following_count` 为 0 → "还没关注任何人"（教用户去作者主页关注）；否则 → "关注的人还没发帖"
- `watch(sort)` 先清空 posts/total 再请求，避免切 tab 时旧内容串台

测试：journey 93/93（新增 8 条）、smoke 70/70；CDP 实测三态：游客引导 / xiaoming「关注 1」2 帖（作者仅拉面忠粉）/ ada（关注 0）空态。

提交 `a6646de`，已推送。文档同步 README、PDR 2.3.1、TechDesigh 3.3.4、AGENTS 决策 18。
