## 图片体积上限：5MB/20MB 不一致 → 统一 10MB

发现的问题不是"没兜底"（`uploadImage` 早就拦了"压缩失败 + 超 5MB"），而是：
1. 三处魔法数字（后端 config/.env 的 5、前端 beforeUpload 的 20），改一处就失配；
2. 判断以 `!compressed` 为前提 → 压缩"成功"但体积仍超标时会漏到后端，变成一句笼统的 400。

改法：后端 `UPLOAD_MAX_MB=10`（config + .env + .env.example）；前端 `api/upload.ts` 导出 `UPLOAD_MAX_MB` / `UPLOAD_MAX_BYTES`，`CreatePostView` 与 `EditPostDialog` 的 `beforeUpload` 引用常量；拦截条件改成只看 `compress.file.size`，并按是否压缩过给不同文案（"压缩后还有 X MB" / "图片有 X MB"）。

为什么是 10 而不是 5：手机直拍原图 3-8MB，5MB 会把正常照片挡在门外；前端压缩后通常 <500KB，这个上限只为"压缩失败退回原图"留余量。

## 移动端底部导航（提交 8564907）

新增 `components/MobileTabBar.vue`，只在 ≤560px 出现：首页 / 食堂 / 发帖(中间抬起) / 通知 / 我的。

**顺带发现一个黑洞**：顶栏的 `.quick-search` 用了全局类 `.hide-sm`（900px 以下 `display:none`），而移动端没有任何其他地方放搜索框——**手机上根本没有搜索入口**。已补 `.search-btn` 图标（≤900px 显示），点进 `/search`（那页本身有完整输入框）。这条最容易在以后重构时被改回去。

布局要点：
- 顶栏窄屏退化成单行「品牌 + 搜索图标 + 账号」，隐藏 `.nav` 和「写食评」（`.write-btn`），底部主按钮取代它。
- **发帖是 button 不是 router-link**（要登录），高亮用 `route.name === 'create'`；`active-class` 对它无效。
- 发帖按钮**绝对定位**（`bottom: 33px`）浮在栏上。第一版塞进 flex 流 + `justify-content: flex-end`，结果五个文字里"发帖"比别人高约 10px；改成绝对定位后给 `.txt` 补 `translateY(10px)`（＝(图标19+间距2)/2），五个文字中心 y 实测 796/796/795/796/796。
- `.shell` 在窄屏补 `padding-bottom: calc(56px + env(safe-area-inset-bottom))`。测遮挡必须**先滚到页面底部再量**，否则 footer 本来就在视口外，会得到假阴性（第一次就踩了）。

验证：e2e 28/28（新增 4 条），CDP 实测游客点发帖 → `/login?redirect=/create`、点搜索 → `/search`、食堂页高亮正确、宽屏 tabbar 隐藏且顶栏完整、桌面截图无异常。build 后 DefaultLayout chunk 5.15KB，首屏 JS 仍 131.69KB。
