## 图片体积上限：5MB/20MB 不一致 → 统一 10MB

发现的问题不是"没兜底"（`uploadImage` 早就拦了"压缩失败 + 超 5MB"），而是：
1. 三处魔法数字（后端 config/.env 的 5、前端 beforeUpload 的 20），改一处就失配；
2. 判断以 `!compressed` 为前提 → 压缩"成功"但体积仍超标时会漏到后端，变成一句笼统的 400。

改法：后端 `UPLOAD_MAX_MB=10`（config + .env + .env.example）；前端 `api/upload.ts` 导出 `UPLOAD_MAX_MB` / `UPLOAD_MAX_BYTES`，`CreatePostView` 与 `EditPostDialog` 的 `beforeUpload` 引用常量；拦截条件改成只看 `compress.file.size`，并按是否压缩过给不同文案（"压缩后还有 X MB" / "图片有 X MB"）。

为什么是 10 而不是 5：手机直拍原图 3-8MB，5MB 会把正常照片挡在门外；前端压缩后通常 <500KB，这个上限只为"压缩失败退回原图"留余量。

## 交付物：一键启动 + README 截图（10:40 完成，本地提交未推）

**一键启动** `dev.py`（仓库根），`start.bat` / `start.sh` 只做转调。决策理由：后端本来就依赖 Python，用它当启动器不必额外要求；两套 shell 各写一遍判断必然走岔。顺序固定：检查运行时 → 建 venv（判断依据是 venv 的 python 能不能 `import fastapi`，不用 `.installed` 标记文件）→ 拷 `.env` → 探 MySQL 端口（只探本机，远程库跳过预检）→ `alembic upgrade head` → `app.seed`（按用户名/名称判重，可无脑每次跑）。

Windows 三个坑：① `npm` 是 `.cmd`，Popen 必须经 shell；② 清理必须 `taskkill /F /T`，否则 vite 派生的 node 子进程占着 5173；③ 输出重定向到文件时 Python 全缓冲，进度像卡死，要 `sys.stdout.reconfigure(line_buffering=True)`。顺带把 SIGTERM / SIGBREAK 归一成 `KeyboardInterrupt`，关终端也能清干净。

实测：先用一个 harness 直接调 `start_backend()` / `start_frontend()` / `stop()`，两端口起来再关掉，确认按进程树能杀干净；再整跑 `python dev.py --no-browser` 后台常驻，8000/5173 均 200。端口被占用时按「已在跑」跳过而不是报错——不然手动起过后端再跑脚本就直接失败。

**截图** `frontend/scripts/shots.mjs` + `npm run shots`，11 张进 `docs/screenshots/`（约 1.1MB）。token 不写脚本，用 `create_access_token(user_id)` 本地生成后走环境变量；脚本里对 `/users/me` 和 `/auth/me` 搞错过一次，真实路径是 `/users/me`。两个等待必须加：`document.images` 全部 complete、以及随机弹窗里「正在翻菜单…」文案消失——第一版就截到了三个骰子还在滚的中间态。

## 安全加固 / 评论回复 / CI / 容器化（11:40 完成，本地提交未推）

**登录限流** `app/services/login_guard.py`：用户名 15 分钟 5 次、IP 20 次，阈值不同是刻意的——校园网一个出口后面几十人，同阈值会让一个人手滑锁掉整栋楼。锁定期内**不校验密码**直接 429，否则响应时间能当侧信道。最大的坑是自己踩的：原本只清用户名计数，结果 IP 计数只增不减，反复跑 smoke 四五轮就会把本机 IP 锁 15 分钟，谁都登不进来。改成成功登录连 IP 一起清（代价：有有效账号的攻击者能重置 IP 计数，这个交换值得）。

**令牌吊销**：`users.token_version` + payload 里的 `ver`。解码时 `ver` 缺失按 0 处理，所以升级那一刻不会把在线会话全踢掉。`get_optional_user` 遇到失效 token 要返回 None 而不是抛 401，否则游客浏览首页会莫名报错。

**评论回复**：`comments.reply_to_id` 自引用 + `ON DELETE SET NULL`（父评删了回复保留，退化成顶层）。通知发给父评论作者而非帖主。列表用 `Comment.id.in_(reply_ids)` 批量查父作者——单条查就是 N+1。前端「回复 @某某」做成可点，点了 `scrollIntoView` 回滚到原评论。

**CI**：单 job 串行（MySQL service → 迁移种子 → uvicorn → smoke/journey → type-check/build → vite → e2e）。ubuntu-latest 自带 Chrome，当初坚持 CDP 不引 puppeteer 在这里白赚一次。**未在真实 Actions 上跑过**，只做了 YAML 解析校验，第一次推上去要盯。
